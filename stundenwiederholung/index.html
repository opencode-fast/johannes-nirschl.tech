Einstieg: Clan-Namen prüfen

Aufgabe: Zeige mit Beweis, ob ein DFA diese Sprache erkennen kann.

start = clan, " ", name
clan  = ("[", name, "]") | ("<", name, ">")
name  = letter, (letter|number|underscore)*

Beweismöglichkeiten:

  • Zustandsdiagramm eines DFA oder NFA
  • Regex
  • Zustandsübergangstabelle eines DFA oder NFA
  • Reguläre Grammatik (siehe unten)
  • Ausführliche Begründung

(\[[a-zA-Z][a-zA-Z0-9_]*\]|<[a-zA-Z][a-zA-Z0-9_]*>) [a-zA-Z][a-zA-Z0-9_]*

Reguläre Grammatik: Jede Regel hat die Form Var → a Var | a mit Var ∈ V (Variable) und a ∈ Σ (Zeichen). Rechts steht genau ein Zeichen, höchstens gefolgt von einer Variablen.

Variationen: Reicht noch ein DFA?

Unser Beispiel lässt sich also mit einem DFA umsetzen. Was passiert, wenn wir die Clan-Regel verändern?

  • Variation 1 (DFA): clan = "[", name, "]"
  • Variation 2 (DFA): clan = ("[", name, "]") | ("<", name, ">")
  • Variation 3 (kein DFA): clan = "[", (clan|name), "]", z. B. [[[Wolf]]] Anna
  • Variation 4 (kein DFA): clan = ("[", (name|clan), "]") | ("<", (name|clan), ">")

Warum kein DFA? Ein DFA merkt sich die Schachtelungstiefe nur über seinen Zustand. Beliebige Tiefe → unendlich viele Zustände nötig, ein DFA hat aber nur endlich viele. ⇒ Variation 3 und 4 sind nicht regulär, lassen sich aber mit einer Grammatik (EBNF) beschreiben.

Wie erweitern wir das Konzept?

Dem DFA fehlt also ein Gedächtnis für die geöffneten Klammern. Wie können wir ihm mehr Speicher geben?

  • Zähler-Variable („[“ +1, „]“ −1): zu speziell, scheitert an Variation 4 ([<Wolf]> Anna).
  • Kellerautomat (nicht lehrplanrelevant): Unser Wort steht auf einem unendlich langen Band, der Lesekopf liest nur in eine Richtung. Die Steuereinheit zeigt den Zustand und hat eine „Erkannt“-Anzeige. Dazu kommt ein Kellerspeicher, der unendlich groß ist (Zugriff nur oben). „[“ → ablegen, „]“ → entnehmen, am Ende leer → passt.

Chomsky-Hierarchie

Mit dem Keller schafft der Automat mehr als ein DFA. Gibt es noch mächtigere Automaten? Einen Überblick, welcher Automat welche Sprachen erkennt, liefert die Chomsky-Hierarchie.

Noam Chomsky (Ende 1950er): vier Sprachtypen, ineinander enthalten (Typ 3 ⊂ Typ 2 ⊂ Typ 1 ⊂ Typ 0).

Links stehen die Grammatiken, die eine Sprache beschreiben, rechts die Automaten, die sie erkennen. Von innen nach außen:

  • Typ 3, reguläre Sprachen: reguläre Grammatik (Var → a Var | a), erkannt von DFA und NFA (Zustandsdiagramm, Zustandsübergangstabelle, Regex). Beispiel: Variation 1 und 2.
  • Typ 2, kontextfreie Sprachen: kontextfreie Grammatik (EBNF, Syntaxdiagramm), links steht genau eine Variable und eine Regel darf sich in der Mitte selbst aufrufen. Erkannt vom Kellerautomaten. Beispiel: Variation 3 und 4.
  • Typ 1, kontextsensitive Sprachen: Eine Variable wird abhängig von ihrer Umgebung (dem Kontext) ersetzt, das Wort wird dabei nie kürzer. Erkannt von der linear beschränkten Turingmaschine, die nur den Bandteil mit der Eingabe benutzen darf. Beispiel: aⁿbⁿcⁿ (abc, aabbcc, …).
  • Typ 0, rekursiv aufzählbare Sprachen: allgemeine Grammatik ohne Einschränkungen für die Regeln. Erkannt von der Turingmaschine.

Je weiter außen ein Typ liegt, desto mächtiger muss der Automat sein. Ein Automat eines äußeren Typs kann auch alle Sprachen der inneren Typen erkennen.

Turingmaschine

Ganz außen in der Hierarchie steht der mächtigste Automat: die Turingmaschine.

Aufbau wie beim Kellerautomaten (unendlich langes Band, Kopf, Steuereinheit mit Zustand und „Erkannt“-Anzeige), aber ohne Keller. Unterschied:

  • bewegt sich in beide Richtungen
  • kann beliebig auf das Band schreiben (Band = Eingabe und Speicher)

Mächtigster Automat: Die Turingmaschine kann alles, was unser Computer kann.

Definition: Eine Turingmaschine ist gegeben durch ein 7-Tupel:

M = (Z, Σ, Γ, δ, z0, □, E)
δ: Z × Γ → Z × Γ × {L, R, N}
  • Z Zustandsmenge, Σ Eingabealphabet, Γ (großes Gamma) Arbeitsalphabet (Γ ⊃ Σ)
  • δ Überführungsfunktion (Menge der Übergänge), muss vollständig für alles definiert sein
  • z0 Startzustand, □ Blank (□ ∈ Γ − Σ), E Menge der Endzustände

Beispiel: Palindrome (abba)

Wie die Turingmaschine ihre beiden neuen Fähigkeiten einsetzt, zeigt ein klassisches Beispiel:

  1. Erstes Zeichen im Zustand merken und löschen
  2. Ans Ende laufen, letztes Zeichen vergleichen: gleich → löschen, sonst reject
  3. Zurück zum Anfang und wiederholen; nichts mehr übrig → accept

Übung: um c erweitern (z. B. cabbac). Lösung für turingmachine.io:

# Erkennt Palindrome aus den Zeichen a, b und c
input: 'cabccbac' # probiere auch: a, ab, bb, babab, cabbac
blank: ' '
start state: start
synonyms:
  accept: {R: accept}
  reject: {R: reject}
# Ein Palindrom ist entweder das leere Wort, ein einzelnes Zeichen
# oder ein (kürzeres) Palindrom, an das vorne und hinten dasselbe Zeichen angehängt wurde.
table:
  start:
    a: {write: ' ', R: haveA}
    b: {write: ' ', R: haveB}
    c: {write: ' ', R: haveC}
    ' ': accept # leeres Wort
  haveA:
    [a,b,c]: R
    ' ': {L: matchA}
  haveB:
    [a,b,c]: R
    ' ': {L: matchB}
  haveC:
    [a,b,c]: R
    ' ': {L: matchC}
  matchA:
    a: {write: ' ', L: back} # gleiches Zeichen an beiden Enden
    b: reject
    c: reject
    ' ': accept # einzelnes Zeichen in der Mitte
  matchB:
    a: reject
    b: {write: ' ', L: back} # gleiches Zeichen an beiden Enden
    c: reject
    ' ': accept # einzelnes Zeichen in der Mitte
  matchC:
    a: reject
    b: reject
    c: {write: ' ', L: back} # gleiches Zeichen an beiden Enden
    ' ': accept # einzelnes Zeichen in der Mitte
  back:
    [a,b,c]: L
    ' ': {R: start}
  accept:
  reject:

Variation 3 als Turingmaschine

Damit können wir zur Einstiegsaufgabe zurückkehren: Was kein DFA schafft, setzen wir jetzt mit einer Turingmaschine um.

  1. Phase 1: Form [ … [ name ] … ] ␣ name prüfen, nur nach rechts und ohne zu schreiben (wie ein DFA)
  2. Phase 2: Klammern paarweise abhaken („[“ → X, „]“ → Y). Bleibt eine übrig → reject, sonst accept

Blank ist □, weil ␣ zur Sprache gehört. X und Y sind Arbeitszeichen (in Γ, nicht in Σ).

# Turingmaschine für Variation 3:  clan = "[", (clan|name), "]"
# Kompaktes Alphabet: Buchstaben a, b, c · Ziffern 0, 1 · _
# Σ = {a, b, c, 0, 1, _, [, ], ␣}   Γ = Σ ∪ {X, Y, □}
# X = abgehakte "[", Y = abgehakte "]", □ = Blank (␣ gehört zur Sprache)
input: '[[ab]] c' # auch testen: [a] b   [[[a_1]]] c0   [[ab] c   [ab]] c   [[ab]]c
blank: '□'
start state: start
synonyms:
  accept: {R: accept}
  reject: {R: reject}
table:
  # Phase 1: Form [ … [ name ] … ] ␣ name prüfen, nur nach rechts, nichts schreiben
  start:
    '[': {R: open}
    [a,b,c,0,1,_,']',' ',X,Y,'□']: reject
  open:       # mindestens eine "[" gelesen
    '[': R
    [a,b,c]: {R: name1}
    [0,1,_,']',' ',X,Y,'□']: reject
  name1:      # Name innerhalb der Klammern
    [a,b,c,0,1,_]: R
    ']': {R: close}
    ['[',' ',X,Y,'□']: reject
  close:      # schließende Klammern
    ']': R
    ' ': {R: sep}
    [a,b,c,0,1,_,'[',X,Y,'□']: reject
  sep:        # nach dem Leerzeichen muss ein Buchstabe kommen
    [a,b,c]: {R: name2}
    [0,1,_,'[',']',' ',X,Y,'□']: reject
  name2:      # Name hinter dem Leerzeichen
    [a,b,c,0,1,_]: R
    '□': {L: back}
    ['[',']',' ',X,Y]: reject

  # Phase 2: Klammern paarweise abhaken, dazu schreiben und in beide Richtungen laufen
  back:       # zurück an den Anfang des Wortes
    [a,b,c,0,1,_,'[',']',' ',X,Y]: L
    '□': {R: count}
  count:      # nächste "[" suchen und abhaken
    X: R
    '[': {write: X, R: findClose}
    [a,b,c]: {R: checkDone}   # keine "[" mehr übrig
    [0,1,_,']',' ',Y,'□']: reject
  findClose:  # passende "]" suchen und abhaken
    ['[',a,b,c,0,1,_,Y]: R
    ']': {write: Y, L: back}
    ' ': reject               # zu viele "["
    [X,'□']: reject
  checkDone:  # sind auch alle "]" abgehakt?
    [a,b,c,0,1,_,Y]: R
    ']': reject               # zu viele "]"
    ' ': accept               # alle Klammern passen zusammen
    ['[',X,'□']: reject
  accept:
  reject:

Zusammenfassung

  • Ob ein DFA reicht, zeigt man mit Zustandsdiagramm, Regex, Zustandsübergangstabelle, regulärer Grammatik oder einer ausführlichen Begründung.
  • DFA und NFA erkennen genau die regulären Sprachen (Typ 3).
  • Beliebig tief verschachtelte Klammern sind nicht regulär: Ein DFA bräuchte dafür unendlich viele Zustände.
  • Ein Zähler ist zu speziell, allgemeiner ist der Kellerautomat mit unendlich großem Kellerspeicher (Typ 2).
  • Die Chomsky-Hierarchie ordnet jedem Sprachtyp eine Grammatik und einen Automaten zu: Typ 3 ⊂ Typ 2 ⊂ Typ 1 ⊂ Typ 0.
  • Die Turingmaschine bewegt sich in beide Richtungen und kann beliebig auf das Band schreiben. Formal ist sie ein 7-Tupel M = (Z, Σ, Γ, δ, z0, □, E), wobei δ vollständig definiert sein muss.
  • Die Turingmaschine ermöglicht die Umsetzung von Typ 0 Sprachen und ist so mächtig, dass sie jegliche Algorithmen in allen Computer nachbilden kann.
  • Mit ihr lässt sich auch Variation 3 umsetzen: erst den Aufbau prüfen, dann die Klammern paarweise abhaken.
